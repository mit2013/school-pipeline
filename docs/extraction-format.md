# 抽出結果のJSON形式

配布物の読み取りを対話セッション(Claude Code など)で行い、その結果をこの形式で
`extracted_events_directory` に置くと、パイプラインは Anthropic API を呼ばずに
カレンダーへ登録します。APIキーも不要です。

読み込んだ後の扱い(同一性による統合、日付の食い違いの検出、他クラス分の除外、
除外ルール、手編集の保護、`--prune`)は、API経由で抽出した場合とまったく同じです。

## 置き場所

**資料1件につきJSONファイル1つ**にしてください。ファイル名は自由ですが、
どの資料から作ったか分かる名前が便利です。

```
inbox/extracted/
  2026M2週末課題2学期.json
  英単語テストについて.json
  川本先生からの連絡.json
```

## 形式

```json
{
  "source": {
    "label": "2026M2週末課題2学期 K.pdf",
    "source_id": "inbox/pdfs/2026M2週末課題2学期 K.pdf",
    "captured_at": "2026-09-05"
  },
  "audience": "3,4,5組",
  "events": [
    {
      "type": "assignment",
      "title": "週末課題 B-1 提出",
      "identity_key": "B-1",
      "date": "2026-09-14",
      "subject": "英語",
      "description": "長文問題集B-1の提出日",
      "confidence": 0.9
    }
  ]
}
```

### source

出典です。省略するとファイル名で補われます。

| 項目 | 説明 |
|---|---|
| `label` | 人が読む表示名。ドライラン結果に出るので、どの資料由来か分かる名前に |
| `source_id` | 資料内で一意な識別子。元ファイルのパスやメッセージIDなど |
| `captured_at` | **配布日/受信日**(`YYYY-MM-DD`)。省略しないでください |

`captured_at` は、同じ予定について資料ごとに違う日付が書かれていたときに、
**どちらが新しいかの判断**に使われます。省略すると古い資料が新しい資料を
上書きすることがあります。

### audience

その資料が誰向けかを、本文から読み取れる場合に書きます(`"3,4,5組"`,
`"B先生担当クラス"`, `"2年生"` など)。読み取れなければ省略します。

同じ配布物がクラス別・担当者別に違う日程で配られることがあり、それを
「予定の変更」と取り違えると、他クラスの日程がそのまま登録されます。
設定の `my_class` と突き合わせて、他クラス向けの予定を落とすのに使われます。

1つの資料の中でクラスごとに違う日程が示されている場合は、**予定ごとに**
`audience` を書いてください(そちらが優先されます)。

### events

| 項目 | 必須 | 説明 |
|---|---|---|
| `type` | ○ | `school_event` / `quiz` / `exam` / `assignment` / `other` |
| `title` | ○ | 短いタイトル |
| `date` | ○ | `YYYY-MM-DD` |
| `identity_key` | | 日付が変わっても同じ予定だと分かる記号。後述 |
| `end_date` | | 複数日にわたる場合の終了日 |
| `start_time` / `end_time` | | `HH:MM`。`start_time` があれば時刻指定の予定になる |
| `subject` | | 科目名。学校全体の行事は省略 |
| `location` | | 場所 |
| `description` | | 根拠となる短い要約 |
| `confidence` | | `0.0`〜`1.0`。省略すると `0.9` |
| `audience` | | この予定だけが特定クラス向けの場合 |

## identity_key — ここが重要です

**日付が変わっても同じ予定だと特定できる短い記号**です。カレンダー上の識別子は
これから作られ、日付を含みません。そのため提出日が後から変更されても、
新しい予定を作らずに既存の予定が移動します。

同じ課題が資料によって違う呼び方で書かれるので、**呼称ではなく番号・記号**を
使ってください。

| 資料の書き方 | identity_key |
|---|---|
| 週末課題 B-1 提出 | `B-1` |
| 長文B-1 | `B-1` |
| 長文問題集のB-1 | `B-1` |
| 2学期中間試験 | `2学期中間試験` |
| 漢字小テスト第2回 | `漢字小テスト第2回` |

科目は含めません(`subject` に入れてください)。全角・半角・大文字小文字・空白の
違いは自動で吸収されるので、`B-1` と `Ｂ－１` は同じ扱いです。

**番号や固有の名前が無く、日付でしか区別できない予定は省略してください。**
省略すると種別・科目・日付で識別されます。毎週の小テストのように、同じ名前が
周回で再登場するものは、むしろ省略したほうが正しく扱えます。

## 読み取るときの注意

実運用で実際に起きた失敗です。

- **同じ日に複数の課題が締め切られる場合は、1件にまとめないでください。**
  B-3 と B-4 は別々のイベントにします。後から一部だけ提出日が変更されることがあり、
  まとめてあると追跡できません
- **実施日が特定できない予定を、期間全体にまたがる予定にしないでください。**
  「9月中のどこか1日、抜き打ちで実施」を 9/1〜9/30 の予定にすると、カレンダー上で
  1か月ずっと表示され続けます。日付が特定できないなら出さないか、`confidence` を
  0.3 以下にします
- **「9月7日の週」のような週単位の指定は、週の起点をそのまま実施日にしないでください。**
  実際の実施日はその週の特定の曜日です。時間割が分からなければ `confidence` を
  下げてください(設定の `extraction_notes` に前提が書かれていることがあります)
- **年はファイル名の数字から取らないでください。** 「250925」のような数字列は資料の
  作成日や整理番号です。本文に年が無ければ、配布日と学校の年度(4月始まり)から
  判断します
- **予定ではない連絡(合格点の説明、再試の扱い、挨拶など)は出さないでください**

## 確認

置いたら、まずドライランで確認します。

```bash
school-pipeline run
```

書式が違うファイルはエラーとしてログに出て、そのファイルだけ読み飛ばされます。
問題なければ `--push` を付けて登録します。
