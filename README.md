# school-pipeline

中学校の学校行事・小テスト・定期試験・課題提出などの予定を、メール(Gmail)・
配布プリント(PDF/写真)・Classroom投稿のコピペテキストから自動抽出し、
Googleカレンダーへ登録するパイプラインです。

自分の家庭で実際に運用しているものを公開しています。学校ごとに配布物の書式は
違うので、そのまま使えるというより、同じ問題を抱えている人が作り替える下敷きに
なればという位置づけです。設計上の判断は [docs/design.md](docs/design.md) に
まとめています。

## 課題意識

- 学校共通アドレスと専門コース用アドレスでメールが分散している
- 教員によって Classroom に登録する人・メールだけの人・週末に金曜締切を連絡する人がバラバラ
- 紙の手帳は書き込まれない
- 結果、子どもが自分の予定を把握できず、ノー勉で小テストに臨む/試験直前に情報整理から始める、という状態になっている

このツールは「予定の存在に気づく」までの確認コストを下げることが目的です。
勉強するかどうかは本人次第ですが、情報を集める作業自体は自動化できます。

## 全体の流れ

```
[Gmail(複数アカウント)]
[配布プリントPDF]         →  抽出(Claude)  →  重複整理  →  確認(dry-run)  →  Googleカレンダー
[写真(OCR)]
[Classroom投稿のコピペ]
```

1. **取得**: Gmail・PDF・写真(OCR)・手動コピペテキストから本文を集める
2. **抽出**: Claude(Anthropic API)に本文を渡し、種別(行事/小テスト/定期試験/課題/その他)・日時・科目などを構造化データとして抽出する。同時に確信度(confidence)も出力させる
3. **整理**: 同じ予定を指す複数の情報源(担任のメール＋教科プリントなど)を1件に統合する。
   統合の鍵は日付ではなく**予定の同一性**(課題番号や試験名)で、提出日が後から変更されても
   同じ予定として扱われる。他クラス向けと分かった予定と、除外ルールに当たった予定はここで外す
4. **確認**: デフォルトはドライラン。登録・更新される予定、確信度が低く除外された予定、
   資料どうしで日付が食い違う予定、カレンダーに残っている削除候補を一覧表示する
5. **登録**: `--push` を付けたときだけ実際に書き込む。再実行しても重複登録されず、
   内容が変わった予定だけ更新される(冪等)。手で編集された予定は上書きしない

同じ予定について資料ごとに違う日付が書かれていた場合は、新しい資料を採用したうえで
**両方の日付と出典を必ず表示します**。同じ配布物がクラス別・担当者別に違う日程で
配られることがあり、それを「変更」と取り違えると間違った日程が登録されるためです。

## セットアップ

### 1. インストール

Python 3.10 以上が必要です。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

OCR(スキャンPDF・写真)を使う場合は、別途 Tesseract OCR 本体と日本語データが必要です。

```bash
# Debian/Ubuntu の例
sudo apt-get install tesseract-ocr tesseract-ocr-jpn
# macOS の例
brew install tesseract tesseract-lang
```

### 2. Google Cloud の準備 (Gmail API / Calendar API)

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成
2. 「Gmail API」と「Google Calendar API」を有効化
3. 「認証情報」→「OAuthクライアントID」→ アプリケーションの種類は「デスクトップアプリ」で作成
4. ダウンロードしたJSONを、学校共通アドレス用・専門コースアドレス用・カレンダー用としてそれぞれ `secrets/` 以下に保存
   (Gmailの2アカウントは別々のGoogleアカウントなので、OAuthクライアント自体は共用しても、認証(トークン取得)はアカウントごとに個別に行います)

`secrets/` と `config.yaml` は `.gitignore` 済みです。認証情報や取得したメール本文をリポジトリにコミットしないでください。

### 3. Anthropic APIキー

`.env` ファイルに保存しておくのがおすすめです(毎回 `export` する必要がなくなります。`.env` は `.gitignore` 済みです)。

```bash
cp .env.example .env
# .env を開いて ANTHROPIC_API_KEY=sk-ant-... の部分を実際のキーに書き換える
```

シェルの環境変数として都度設定したい場合は、代わりに以下でも構いません(その場合、そのシェルではClaude Code自体のログインより優先されてしまう点に注意してください):

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
```

### 4. 設定ファイル

```bash
cp config.example.yaml config.yaml
```

`config.yaml` を開き、`gmail_accounts` の `credentials_path`、`pdf_directory` などを環境に合わせて編集してください。
使わない取得元(例: 写真OCRを使わない)は該当行を削除して構いません。

### 5. 初回認証

Gmailアカウントごと、カレンダーそれぞれで一度だけブラウザ認証が必要です。

```bash
school-pipeline auth-gmail --account school_common
school-pipeline auth-gmail --account course_specific
school-pipeline auth-calendar
```

## 使い方

### 1. まずドライランで確認する

```bash
school-pipeline run
```

抽出された予定の一覧、確信度が低くて除外された予定、重複の可能性がある予定、
カレンダーに対する差分(新規/更新/変更なし件数)が表示されます。実際の書き込みは行われません。

### 2. 問題なければ実際に登録する

```bash
school-pipeline run --push
```

### 3. 要らない予定を消す

「一旦登録したが、うちの子には関係ない」「書き方が曖昧で毎日表示されてノイズになる」
といった予定は、**除外ルール**で登録対象から外します。

```bash
school-pipeline exclude --title-contains 身だしなみ検査 --reason "本人に該当しないため"
school-pipeline exclude --list
```

ルールは `exclusions.yaml` に追記されます(手で書いても構いません。書き方は
`exclusions.example.yaml` を参照)。条件は AND で組み合わさるので、条件を足すほど
対象は狭くなります。

ルールを足しただけでは、**すでにカレンダーにある予定は消えません**。
`--prune` を付けると、パイプラインが登録したもののうち今回の抽出結果に無い予定を削除します。

```bash
school-pipeline run                  # 削除候補の一覧が出るだけ
school-pipeline run --push --prune   # 実際に削除する
```

`--prune` は除外ルール以外の後始末にも効きます。提出日が変更されて古い日付に取り残された
予定や、`inbox/` から資料を消したあとに残った予定も、まとめて片付きます。
**必ず先にドライランで削除候補を確認してください。**
手で編集された予定は `--prune` でも消えません。

### 4. Classroomの投稿だけは手動で

ClassroomはAPI連携していないため、教員がClassroomにしか投稿しない情報は自動取得できません。
運用でカバーする場合は、投稿本文をコピーして `inbox/manual/` に `.txt` として保存するだけで、
次回の `run` から自動的に取り込まれます。

配布プリントをスマホで撮影した場合は `inbox/photos/` に、PDFでもらった場合は `inbox/pdfs/` に置いてください。

### 5. 定期実行する

cron で毎朝実行する例(ドライラン結果をメールで確認し、問題なければ手動で `--push` する運用を推奨):

```cron
0 7 * * * cd /path/to/school-pipeline && .venv/bin/school-pipeline run >> run.log 2>&1
```

慣れてきたら `run --push` を直接スケジュールしても構いませんが、抽出ミスに気づけるよう、
最初のうちはドライラン結果を毎回確認することを推奨します。

## 精度・安全性についての考え方

- LLMによる抽出には誤り(誤読・日付の取り違え)がありえます。**確信度が低い予定は自動的にカレンダー登録から除外され、一覧表示のみ**されます(`confidence_threshold` で調整可能)
- 似た予定が別ソースから複数出てきた場合、機械的に断定して統合すると誤って別の予定を1つに潰してしまう危険があるため、**重複候補は一覧に出すだけで自動統合しません**
- カレンダー同期は `extendedProperties` に予定の識別子を保存して行うため、**同じ予定を何度実行しても重複登録されません**。内容が変わった場合のみ既存の予定を更新します
- 課題番号や試験名のように「日付が変わっても同じもの」と分かる予定には識別子を付けており、**提出日が後から変更された場合は新規登録ではなく既存の予定が移動します**。古い日付に取り残された予定は削除候補として報告されます
- 同じ課題について資料ごとに違う日付が書かれていた場合、**新しい資料を採用したうえで、両方の日付と出典を必ず一覧に表示します**。黙って片方を選ぶことはしません
- 同じ種類のプリントがクラス別・担当者別に別バージョンで配られることがあります。資料に対象の明記があり、それが食い違う場合は**「変更」とみなさず、どちらも登録しません**。設定の `my_class` に自分の子のクラスを書いておくと、対象の違う資料を取り込んだ時点で警告が出ます
- 日付が特定できない連絡(「9月中のどこか1日、抜き打ちで実施」など)が期間まるごとの予定として抽出されると、カレンダー上で毎日表示され続けてしまいます。`max_span_days` を超える終日イベントは確信度を下げ、登録対象から外します
- 削除は既定では行いません。`--prune` を明示したときだけ、パイプラインが登録した予定のうち抽出結果に無くなったものを消します。**手で編集された予定は `--prune` でも消しません**

## テスト

外部API(Anthropic / Google)を実際に呼び出さず、フェイクのクライアント/サービスに差し替えてロジックを検証しています。

```bash
pip install -e ".[dev]"
pytest
```

## リポジトリの構成

```
src/school_pipeline/
  sources/         取得(Gmail / PDF / 画像OCR / 手動テキスト)
  extraction/      Claudeによる構造化抽出とプロンプト・ツール定義
  pipeline/        同一性による統合、除外ルール、キャッシュ、費用計測
  calendar_sync/   Googleカレンダーへの冪等な同期
  cli.py           コマンドライン
tests/             外部APIを呼ばずにロジックを検証する(137件)
docs/design.md     設計上の判断と、その理由
```

## 個人情報の扱い

学校からの配布物には、子どもの氏名・クラス・学校名・教員名が含まれます。
これらがリポジトリに入らないよう、置き場所を分けています。

- `config.yaml` / `exclusions.yaml` / `secrets/` / `inbox/` / `.env` は **gitignore 済み**
- 追跡しているのは `config.example.yaml` などの雛形だけで、値はすべて一般的な例
- コード中のコメントやテストの例にも、実在する学校名・コース名・行事名・教員名は
  書きません。断片的でも組み合わせると学校が特定できるためです

フォークして使う場合も、この分け方は崩さないことをおすすめします。
